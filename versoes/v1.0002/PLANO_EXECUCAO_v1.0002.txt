OBJETIVO PRINCIPAL
--------------------------------------------------------------------------------
Criar uma nova estrutura completa de configuracoes.html, dentro da versao
v1.0002, voltada para um segmento de e-commerce de venda de e-books, apostilas,
cursos e materiais de estudos teologicos.

O painel atual nao sera usado como base visual. A nova versao deve ser pensada
como um sistema administrativo real, modular, responsivo, seguro e pronto para
crescer.

Por enquanto, o index.html continua como modulo publico unico de venda/vitrine
de materiais de estudo. Em etapa posterior, ele sera reestruturado para consumir
os dados reais do novo painel de produtos e configuracoes.

PRINCIPIO DE ARQUITETURA
--------------------------------------------------------------------------------
O painel sera dividido em modulos, acessados por navegacao interna via hash:

  configuracoes.html#/dashboard
  configuracoes.html#/venda
  configuracoes.html#/produtos
  configuracoes.html#/relatorio
  configuracoes.html#/configuracoes

Cada modulo deve funcionar como uma area independente, mas compartilhando:

  - sessao autenticada Supabase
  - cliente REST Supabase
  - sistema de toast
  - modal de confirmacao
  - layout base
  - estado global simples em JavaScript
  - utilitarios de formatacao, seguranca e validacao


MODULOS DO PAINEL
================================================================================

1. MODULO DASHBOARD
--------------------------------------------------------------------------------
Objetivo:
Dar uma visao rapida da operacao da loja Kerigma.

Componentes:

  - Card: produtos cadastrados
  - Card: produtos ativos
  - Card: vendas do dia
  - Card: receita do mes
  - Card: pedidos pendentes
  - Card: ticket medio
  - Lista: ultimas vendas
  - Lista: produtos mais vendidos
  - Area: atalhos rapidos

Atalhos rapidos:

  - Nova venda
  - Novo produto
  - Ver relatorio
  - Configurar site

Experiencia desejada:

  - Interface limpa, operacional e facil de escanear.
  - Visual de painel profissional, sem cara de landing page.
  - Cards compactos, tabelas claras e bons estados vazios.

Estados previstos:

  - Carregando dados
  - Sem vendas ainda
  - Sem produtos cadastrados
  - Falha ao carregar dados
  - Sessao expirada


2. MODULO VENDA
--------------------------------------------------------------------------------
Objetivo:
Funcionar como um mini PDV para vender e-books e materiais teologicos.

Fluxo principal:

  1. Buscar produto
  2. Adicionar ao carrinho
  3. Informar dados do cliente
  4. Escolher forma de pagamento
  5. Aplicar desconto, se houver
  6. Finalizar venda
  7. Gerar resumo do pedido
  8. Copiar mensagem para WhatsApp

Campos da venda:

  - Nome do cliente
  - WhatsApp do cliente
  - Email do cliente
  - Produtos selecionados
  - Quantidade
  - Subtotal
  - Desconto
  - Total
  - Forma de pagamento
  - Status da venda
  - Observacoes

Formas de pagamento:

  - Pix
  - Cartao
  - Dinheiro
  - Link externo
  - WhatsApp

Status da venda:

  - pendente
  - pago
  - cancelado
  - reembolsado

Funcionalidades criativas:

  - Carrinho lateral no desktop.
  - Carrinho em gaveta no mobile.
  - Botao para copiar resumo do pedido.
  - Botao para abrir WhatsApp com mensagem pronta.
  - Recibo simples exibido ao final.
  - Indicador visual de venda pendente/paga.

LAYOUT E UX
================================================================================

Estrutura visual:

  - Sidebar fixa em desktop
  - Topbar compacta em mobile
  - Menu hamburguer em telas pequenas
  - Conteudo principal em largura total
  - Modais apenas para confirmacoes e formularios longos quando fizer sentido
  - Tabelas responsivas com versao compacta no mobile
  - Botoes com icones Font Awesome

Tonalidade visual:

  - Profissional, leve e confiavel
  - Inspirado em painel SaaS/operacional
  - Paleta Kerigma mantida, mas com mais respiro:
      azul escuro #001a47
      verde WhatsApp #25D366
      branco #ffffff
      cinzas neutros
      detalhes dourados discretos, se combinarem com o tema teologico

Regras de UX:

  - Nao esconder a acao principal.
  - Toda exclusao precisa de confirmacao.
  - Todo salvamento precisa de feedback.
  - Todo formulario precisa de estado carregando.
  - Todo modulo precisa ter estado vazio bem resolvido.
  - Mobile deve ser tao usavel quanto desktop.


BANCO DE DADOS PROPOSTO
================================================================================

Tabela: products
--------------------------------------------------------------------------------
Finalidade:
Catalogo de produtos digitais e materiais de estudo.

Campos sugeridos:

  id uuid primary key
  title text not null
  slug text unique
  short_description text
  description text
  category text
  price numeric not null default 0
  promo_price numeric
  cover_image text
  delivery_url text
  whatsapp_message text
  is_active boolean default true
  is_featured boolean default false
  sort_order integer default 0
  created_at timestamptz default now()
  updated_at timestamptz default now()


Tabela: sales
--------------------------------------------------------------------------------
Finalidade:
Registro principal de cada venda.

Campos sugeridos:

  id uuid primary key
  customer_name text
  customer_phone text
  customer_email text
  subtotal numeric not null default 0
  discount numeric not null default 0
  total numeric not null default 0
  payment_method text
  status text default 'pendente'
  notes text
  created_at timestamptz default now()
  updated_at timestamptz default now()


Tabela: sale_items
--------------------------------------------------------------------------------
Finalidade:
Itens de cada venda.

Campos sugeridos:

  id uuid primary key
  sale_id uuid references sales(id) on delete cascade
  product_id uuid references products(id)
  product_title text
  unit_price numeric not null default 0
  quantity integer not null default 1
  total numeric not null default 0
  created_at timestamptz default now()


Tabela: site_settings
--------------------------------------------------------------------------------
Finalidade:
Configuracoes publicas e comerciais do site.

Campos sugeridos:

  id integer primary key default 1
  site_name text
  hero_title text
  hero_subtitle text
  cta_title text
  cta_text text
  whatsapp text
  email text
  address text
  hero_image text
  default_whatsapp_message text
  after_purchase_message text
  currency text default 'BRL'
  default_payment_method text default 'pix'
  default_sale_status text default 'pendente'
  updated_at timestamptz default now()


RLS / SEGURANCA
--------------------------------------------------------------------------------
Politicas esperadas:

  products:
    - leitura publica apenas de produtos ativos
    - leitura admin de todos os produtos
    - escrita apenas admin

  sales:
    - sem leitura publica
    - leitura/escrita apenas admin

  sale_items:
    - sem leitura publica
    - leitura/escrita apenas admin

  site_settings:
    - leitura publica
    - escrita apenas admin

Observacao:
Como o projeto usa Supabase diretamente no frontend, a seguranca depende das
politicas RLS. Antes de publicar qualquer painel com vendas reais, validar RLS
no banco e testar acesso anonimo manualmente.
